🎯 Local Life Agent - 完整逻辑流程

📋 核心原则
✅ 正确做法
  • 使用真实高德API获取POI数据
  • 使用MiMo进行意图解析
  • 使用Tavily进行联网核验
  • 所有返回内容必须是中文
  • 失败时返回中文阻断提示
  • Mock数据只在test profile中使用
❌ 错误做法
  • 使用SeedData中的英文假数据
  • 使用关键词匹配代替LLM
  • 返回英文分享消息
  • 失败时静默降级到Mock
  • 使用硬编码的假POI名称
  • 在生产环境使用Mock数据
⚠️ 当前问题

SeedData.java 中使用英文名称（如 "Family Forest Lab", "Coast Science Theater"），MockTools.java 中的 share() 方法生成英文消息。这些在正常环境中是不允许的。

🔄 完整运行链路（8个步骤）
1
用户输入中文需求
用户输入自然语言，如"今天下午带老婆孩子出去玩，孩子5岁"
前端输入框 POST /api/plans
↓
2
需求解析 Agent → MiMo
调用MiMo解析意图，输出结构化JSON：人数、时间、城市、出发点、硬约束、偏好
MiMo API mimo-v2.5-pro 结构化输出
// 输入 "今天下午带老婆孩子出去玩，孩子5岁，老婆在减肥，别离家太远" // 输出 { "scenario": "family", "group": { "total": 3, "composition": "2大1小", "childAge": 5 }, "time_window": { "start": "14:00", "end": "20:00" }, "location": { "city": "大连", "radius": "nearby" }, "hard_constraints": ["kid_friendly", "low_calorie_preferred"] }
↓
3
联网核验 Agent → Tavily
调用Tavily查近期活动、口碑、排队、闭店、天气等信息
Tavily API Web Search 实时信息
✅ 核验内容
  • 近期活动：是否有展览、演出、节庆
  • 口碑评价：景点/餐厅的最新评价
  • 排队情况：热门地点的排队时长
  • 闭店信息：是否有临时关闭
  • 天气预报：下午是否有雨
↓
4
POI Agent → 高德Web服务
调用高德POI搜索，根据真实关键词和范围检索地点
高德Web服务API POI搜索 中文结果
// 搜索关键词（根据场景动态生成） 家庭场景: "亲子 乐园 博物馆" 朋友场景: "聚餐 KTV 密室" 减肥场景: "轻食 健康餐 沙拉" // 搜索范围 城市: 大连 范围: 10km（附近）/ 全城
↓
5
路线 Agent → 高德距离/路线接口
调用高德路线规划，计算真实距离和耗时
高德路线API 步行/驾车 真实耗时
💡 计算内容
  • POI间的真实距离（米）
  • 步行/驾车的预计耗时
  • 总行程时间是否在4-6小时内
  • 是否需要调整路线
↓
6
方案生成 Agent → MiMo
调用MiMo，只允许基于真实候选地点生成Top-3中文方案
MiMo API 中文输出 防编造
// 输入：真实POI列表 + 用户约束 候选地点: [大连森林动物园, 星海广场, ...] 用户约束: 儿童友好, 低卡, 4-6小时 // 输出：Top-3中文方案 方案1: { "name": "亲子轻松游", "timeline": [ { "time": "14:00", "place": "大连森林动物园", "duration": "2小时" }, { "time": "16:30", "place": "轻食餐厅", "duration": "1.5小时" }, { "time": "18:30", "place": "星海广场散步", "duration": "1小时" } ] }
↓
7
中文校验器 + 防编造校验器
检查输出是否合规，失败则阻断，不返回假方案
校验规则 阻断机制 中文检查
中文校验
  • 所有可见文案必须是中文
  • 不能出现英文地名
  • 不能出现英文菜名
防编造校验
  • 所有地点必须来自高德API
  • 不能使用SeedData中的假数据
  • 失败时返回阻断提示
↓
8
用户确认 → 执行（Mock）
用户确认方案后，执行订座、购票、配送（暂时Mock），订单和分享文案必须中文
Mock订单 中文消息 分享功能
// 订单（Mock） { "orderNo": "MOCK-DINING-abc123", "action": "订座", "target": "轻食餐厅", "status": "已确认" } // 分享消息（中文） "搞定啦！下午2点出发，先去大连森林动物园，然后去轻食餐厅吃饭，最后在星海广场散步。所有预订都已安排好！"
🤖 Agent架构设计
💡 设计原则

v1使用1个LLM（MiMo），多个Agent角色共享。不是每个Agent一个模型，而是专业化分工 + 共享LLM。

🧠 IntentParserAgent

职责：意图解析

工具：MiMo API

输入：用户自然语言

输出：结构化JSON

🔍 SearchVerifierAgent

职责：联网核验

工具：Tavily API

输入：地点+场景

输出：实时信息

📍 POISearchAgent

职责：POI搜索

工具：高德API

输入：关键词+范围

输出：真实POI列表

🗺️ RouteOptimizerAgent

职责：路线优化

工具：高德路线API

输入：POI列表

输出：最优路线

📝 PlanGeneratorAgent

职责：方案生成

工具：MiMo API

输入：真实POI+约束

输出：Top-3方案

🔧 ExceptionRecoveryAgent

职责：异常恢复

工具：MiMo API

输入：异常类型

输出：替代方案

  2. 填写真实密钥到 config.py
  3. 运行脚本生成 Spring Boot 配置
  4. 启动后端服务
  5. 启动前端服务
⚠️ 安全提醒

config.py 必须加入 .gitignore，不能提交到代码仓库！

🛡️ 失败策略
失败场景 处理方式 返回内容
MiMo API调用失败 降级到关键词匹配 使用简化意图继续
高德API失败/Key缺失 返回中文阻断提示 "抱歉，暂时无法获取地点信息，请稍后重试"
Tavily API失败 跳过联网核验 继续流程，trace记录
POI结果为空 返回中文阻断提示 "抱歉，未找到符合条件的地点"
LLM输出不合规 返回中文阻断提示 "抱歉，方案生成失败，请重试"
餐厅无座位 自动替换餐厅 返回替代餐厅
活动无票 自动替换活动 返回替代活动
行程超时 缩短可选活动 返回调整后方案
